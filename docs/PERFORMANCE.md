# Скорость голосового перевода

Голосовой перевод проходит три шага: распознавание речи (MMS-1B), перевод (NLLB-200) и озвучивание (MMS-TTS или EveryVoice). Модели уже выбраны с учётом качества и работы без интернета, поэтому ускорение касается того, как приложение их запускает.

## Что изменилось

| Где терялось время | Что сделано |
| --- | --- |
| Каждый запрос заново читал веса: 1 ГБ распознавателя, 895 МБ переводчика и голос. Загрузка занимала несколько секунд на каждом шаге. | Модели остаются в памяти между запросами (`ModelCache`). Объём зависит от оперативной памяти телефона: примерно 55 % ОЗУ минус 700 МБ, не больше 3,5 ГБ. При нехватке памяти Android приложение сразу освобождает модели. |
| Первая запись и первый перевод ждали загрузки. | Пока пользователь читает или набирает текст, приложение заранее загружает распознаватель, переводчик и голос для выбранного направления, если они помещаются в память. Любой запрос пользователя важнее подготовки. |
| Первый перевод на шона после каждого запуска считал SHA-256 файла 476 МБ. | Контрольная сумма запоминается для того же размера и времени изменения файла. |
| При переводе на русский загружался второй декодер NLLB 476 МБ. | Если подготовленный декодер для шона уже есть, он же используется для русского. Результат перевода не меняется: модель выдаёт тот же жадный вариант. |
| Распознавание и озвучивание использовали 2 потока CPU. | Используется половина ядер, от 2 до 4. |
| Тишина в начале и конце записи распознавалась наравне с речью. | Перед распознаванием длинная тишина по краям обрезается с запасом 0,36 с. Если контраст между речью и тишиной неясен, запись не меняется. |
| Кнопка микрофона была маленькой иконкой в углу. | Микрофон стал крупной круглой кнопкой, которую удобно удерживать во время разговора. |
| Русский перевод озвучивался по частям с ожиданием между ними. | Следующая часть синтезируется, пока звучит текущая, как уже было для шона. |

В журнале Android (`adb logcat -s ShonaVoice`) видны строки `stage=... elapsed_ms=...` для каждого шага, включая фоновую подготовку `stage=prepare`.

## Выходной слой переводчика в INT8 (1.1.0)

Профиль ONNX Runtime (`tools/profile_nllb.py`) показал, что в поставляемом декодере NLLB
выходной слой на каждом шаге распаковывал всю матрицу словаря (256 206 × 1024) из INT8 во float:
около 70 % времени перевода. `tools/fast_decoder.py` строит рецепт производного декодера, в
котором эта матрица умножается напрямую через MatMulInteger, как остальные слои, а транспонирование
выполняется один раз для обеих ветвей графа. Приложение собирает этот декодер на телефоне из уже
установленного `decoder.onnx` (около 2 КБ новых байтов), новые веса не скачиваются.

Замер на 4 потоках x86, 12 предложений: 610 → 27 мс на токен; 11 из 12 переводов совпали
дословно. Пиковая память декодера: 2,25 → 1,55 ГБ. Шаг с тремя вариантами (beam) стоит
примерно в 1,3 раза больше, чем один вариант, поэтому по умолчанию снова сравниваются три
варианта перевода на шона.
